## Что это
**Командный центр БумБастик** — внутренний BizOps-пульт для владельцев и
руководства **сети игровых парков** (MARI / Москва; Охта Молл, Питерленд, Июнь /
СПб). **Обзорный инструмент, не таск-трекер и не ERP.** PWA на GitHub Pages.
Только чтение, без CRUD изнутри.

**Информационная архитектура — 4 вкладки** + под-страница `Парки`
(не вкладка, открывается с Главной, с «Назад») + **глобальный парк-контекст**
(`Вся сеть / MARI / Охта Молл / Питерленд`; «Июнь» в архитектуре есть, но
до открытия скрыт в UI флагом `enabled:false` в `src/data/parks.js`):
**Главная** (командная дека — стартовая) · **Аналитика** (Pulse) ·
**Проекты** (Initiatives) · **Материалы** (Library).

Главная = **дека из 3 баннеров-разделов** (Аналитика/Проекты/Материалы)
с местом под 1–2 ключевые цифры (сейчас плейсхолдер) + вторичная кнопка
**«Парки»**. Карточек парков на Главной нет; они уехали в справочную
под-страницу `Парки` (некликабельные контейнеры, станут кнопками при
появлении статы).

Парк-контекст активен: store — `src/composables/useParkContext.js`. Работает
по **чистому разделению** (TZ-3.3) — но **семантика «Вся сеть» зависит от
раздела**:

- **Проекты:** `current === 'network'` (дефолт) → только общесетевые
  (`parks === 'network'`); `current = id парка` → только проекты этого
  парка. Общесетевые в виды парков **не попадают**.
- **Аналитика:** общесетевых строк не бывает (каждая строка имеет конкретный
  парк), поэтому `'network'` = **агрегат по всем паркам по правилам §3
  контракта**. Это сознательное расхождение с Проектами, явно
  маршрутизируется через `computeContext()` в `analyticsAggregate.js`.

Выбор парка делается **лёгкой монохромной пилюлей-фильтром** в шапке
навигации на рабочих разделах (Аналитика/Проекты/Материалы — `parkFilter:
true` у вкладки). Тап по пилюле открывает bottom-sheet chooser
(`ParkPickerSheet.vue`). Имена парков — единый справочник `src/data/parks.js`
(с флагом `enabled`; chooser/пилюля ходят через `PARKS_VISIBLE_BY_CITY`).
**Парк-бейджей на карточках нет** (scope задаёт фильтр); в `ProjectDetail`
парки — обычное текст-поле. На Материалах фильтр пока «вхолостую» — данные
подхватят позже.

## Стек (зафиксирован — не менять без согласования)
Vue 3 (`<script setup>`, JS, не TS) · Vite 8 · Tailwind 3.4 + PostCSS + autoprefixer
· lucide-vue-next 1 · рукописный PWA-слой (`public/manifest.json` + `public/sw.js`,
без vite-plugin-pwa) · хостинг GitHub Pages через GitHub Actions
(`.github/workflows/deploy.yml`), Node 22. Источник данных (Фаза 4) — gated Google
Apps Script (логин/пароль, read-only JSON). Бэкенда нет.

## Жёсткие параметры
- Репозиторий `boom-cmd`; **`base: '/boom-cmd/'`**. При смене домена на `b00m-cmd.ru`
  → `base: '/'` + `public/CNAME`. `base` прошит в: `vite.config.js`, `public/manifest.json`,
  `public/sw.js`, `index.html`. Внутренние пути — через `import.meta.env.BASE_URL`.
- **Платформа: mobile-first под iPhone, Apple HIG.** ПК не целевой — на десктопе
  мобильная колонка `max-w-[430px]` по центру. Tab bar внизу (только навигация),
  navigation bar с large title вверху, тач-таргеты ≥44pt, safe-area через `env(...)`.
- **Вертикаль и прощающие жесты.** Скролл вверх-вниз; **горизонтального свайпа
  контента нет.**
- **Язык:** данные/значения — английский; UI — русский (слой перевода в `src/i18n/`).
- Права на данные = доступы к источнику, НЕ роли в коде. Фронт read-only.

## Дизайн — ИСТОЧНИК ИСТИНЫ: `docs/DESIGN-STANDARD-boom-cmd.md`
- **Светлая тема по умолчанию.** Тёмная — будущий свап через `[data-theme="dark"]`.
- **Только семантические токены `var(--…)`. Хардкод hex в компонентах ЗАПРЕЩЁН.**
  Все hex живут в одном месте — `src/styles/main.css` (`:root`).
- **Монохром по умолчанию, цвет — по функции** (`PRODUCT-PRINCIPLES §7`,
  `DESIGN-STANDARD §3.4`): срочный приоритет (`--negative`), активное состояние
  (`--accent`), активный парк-фильтр (чёрный бедж — тон), данные в графиках
  Аналитики. Всё прочее серое.
- **Текст всегда монохромный:** чёрный/серый на светлом; белый на тёмной заливке
  (синий/красный/`--text`-чёрный); тёмный ink на светлой заливке (жёлтый).
  Цветного текста нет.
- Брендовый акцент — жёлтый `--accent #FFC833`, **только заливка** (напр. пилюля под
  иконкой активной вкладки с `--accent-ink`). Активная вкладка: подпись `--text`,
  индикатор — жёлтая заливка; неактивные — `--text-muted`.
- **Шапка навигации — large-title-collapse** (механика Ф1, восстановлена в
  ревизии 3.2): крупный центрированный заголовок в потоке + компактная
  стики-панель с компактным центрированным заголовком, проявляющаяся при
  `scrollTop > 28`. **Намеренное отклонение от Ф1:** заголовок центрированный
  (а не лево-выровненный iOS-default). Слева в компактной строке — back-кнопка
  при заходе вглубь; справа — компактная пилюля парк-фильтра. Большая пилюля
  фильтра — в потоке под крупным заголовком.

Ключевые токены (полный набор — в стандарте §3.6 и в `src/styles/main.css`):
`--bg #F7F6F3` · `--surface #FFFFFF` · `--surface-2 #F1F0EC` · `--line #E3E1DB` ·
`--text #1C1B18` · `--text-secondary #45433E` · `--text-muted #6F6D66` ·
`--accent #FFC833` / `--accent-ink #1C1B18` · сигналы: `--positive #2F9E54`
`--negative #D92D20` `--info #2563EB` `--warning #FFC833` · служебные:
`--ink-on-color #FFFFFF` (текст на тёмной заливке) · `--scrim` (затемнение под модалкой).

Blur «стекла» — только Tailwind-утилита `backdrop-blur` (чтобы autoprefixer добавил
`-webkit-backdrop-filter`; на iOS Safari без префикса не отрисуется). Нативный
Liquid Glass не имитируем.

## Структура кода (актуально для Фазы 5a)
- `src/App.vue` — конфиг 4 вкладок (Главная стартовая) + конфиг под-страниц
  (сейчас `parks`). Флаг `parkFilter: true` у вкладки → пилюля активного
  парк-фильтра в шапке.
- `src/components/AppShell.vue` · `NavigationBar.vue` · `TabBar.vue` — оболочка.
  `AppShell` держит `collapsed`/`onScroll` (порог 28px), сброс при смене
  вкладки/под-страницы. `NavigationBar` рендерит крупный центрированный
  заголовок в потоке + компактную стики-панель, и сам кладёт пилюлю
  парк-фильтра в обе позиции (центр большой / справа компактная) — если
  у текущего экрана `parkFilter: true`. Под заголовком — опциональный
  caption (мелкая строка типа «данные от 11.06.2026»), управляется
  модульным синглтоном `useNavCaption`.
- `src/components/navigation/ParkFilterPill.vue` — лёгкая монохромная пилюля
  с шевроном; поддерживает `compact` режим для стики-панели.
- `src/components/navigation/ParkPickerSheet.vue` — bottom-sheet chooser
  (выбор парка). Ходит через `PARKS_VISIBLE_BY_CITY`, чтобы парки с
  `enabled:false` (Июнь до открытия) не показывались.
- `src/components/home/SectionBanner.vue` — крупный баннер деки на Главной.
- `src/components/parks/ParkCard.vue` — некликабельная справочная карточка
  парка (имя/город/пустой слот).
- `src/components/projects/` — карточка/секция/детали проекта, PriorityIcon,
  DirectionChip, MilestoneMark.
- `src/components/analytics/` — секция Аналитики (Фаза 5a):
  - `PeriodSegmented.vue` — сегмент-переключатель «Месяц/3 мес/12 мес»
    (лейбл `month` подменяется именем актуального месяца);
  - `SectionTabs.vue` — горизонтальная лента вкладок (Сводный + 6
    доменов) с edge-gradient масками подсказки скрытого хвоста;
  - `KpiTile.vue` — KPI-плитка Сводного экрана; бейдж неполноты в
    фиксированном слоте под шапкой; sparkline тонкой линией;
  - `MetricCard.vue` — карточка значения слоя 1 (`emphasis=true` →
    тёмная) / слоя 2 (светлая). Тёмная карточка реализована
    двухуровневым подходом: внешний article держит фон/цвет, внутренний
    div держит override CSS-токенов для детей (`--text/--text-muted/...`
    → color-mix от `--ink-on-color`);
  - `MonthlyTrend.vue` — мини-чарт SVG (bar / line / sparkline) без
    зависимостей. Для null значений в баре — фантомный rect с диагональной
    штриховкой (SVG `<pattern>`). Sparkline нормализован MIN..MAX,
    с полупрозрачной area-заливкой и точками-маркерами на endpoints;
  - `CompletenessBadge.vue` — пилюля «N из M мес» / «N из M парков»
    (показывается только при неполноте);
  - `MultiDateNotice.vue` — подпись «состояние на разные даты» для
    сетевых last-month-метрик, когда у парков последние месяцы расходятся;
  - `Layer3Stub.vue` — заглушка «в разработке»;
  - `views/{HomeView,RevenueView,PlayersView,CardsView,GameEconView,
    PrizesView,ReviewsView}.vue` — 7 видов; HomeView рендерит 8 KPI-плиток.
- `src/screens/{Home,Analytics,Projects,Materials,Parks}Screen.vue` — экраны.
  `AnalyticsScreen` держит локальное состояние period + tab, ставит
  caption через `useNavCaption` на activate/deactivate (keep-alive).
- `src/composables/useAppNav.js` — модульный синглтон навигации.
- `src/composables/useParkContext.js` — модульный синглтон парк-контекста
  (`current` ∈ {`'network'`, id парка}).
- `src/composables/useNavCaption.js` — модульный синглтон для caption
  над H1 в шапке. Экраны ставят/чистят на activate/deactivate.
- `src/composables/useProjects.js` — точка работы с источником проектов.
- `src/composables/useAnalytics.js` — точка работы с источником аналитики
  (паттерн = useProjects; `?action=analytics`; `VITE_ANALYTICS_API` →
  фолбэк `VITE_PROJECTS_API`; dev-fallback на мок, prod без env =
  громкая ошибка).
- `src/composables/analyticsAggregate.js` — **чистый JS-модуль** (нет
  vue/DOM), реализует §3/§4 контракта построчно: СУММА / ПЕРЕСЧЁТ
  (одно- и кросс-доменный) / ВЗВЕШЕННОЕ (одно- и кросс-доменное) /
  ПОСЛЕДНИЙ месяц (с `byPark`/`multipleDates` для сети) / МАКСИМУМ /

- `src/composables/useAccessKey.js` — общий гейт на весь вход.
- `src/data/parks.js` — единый справочник парков с флагом `enabled`.

  `PARKS_BY_ID` для маппинга данных.
- `src/data/projects.mock.json` — мок проектов.
- `src/data/analytics.mock.json` — мок аналитики (форма = контракту).
- `src/i18n/projects.js` — словари EN→RU для Проектов.
- `src/i18n/analytics.js` — словари EN→RU для Аналитики (по §2
  контракта) + форматтеры (formatRub/Rub2/Pct/Growth/Compact и др.).
- `src/styles/main.css` — токены `:root` + светлый холст + base.
- `scripts/verify-analytics.mjs` — самопроверка 8 чисел приёмки и
  кейсов пропусков, чтобы регрессия в `analyticsAggregate.js` сразу
  выпала. Запуск: `node scripts/verify-analytics.mjs`.

## PWA / Service Worker (TZ-3.3 §5)
`public/sw.js` — рукописный. CACHE_NAME содержит build-id (плейсхолдер
`__BUILD_ID__` заменяется на `Date.now()` хуком `closeBundle` в
`vite.config.js`). Стратегии: навигации — network-first с обновлением
кэшированного `index.html`; GET-ассеты с хешированным именем — cache-first.
`skipWaiting` + `clients.claim` + чистка старых кэшей. `postMessage`
клиентам после активации — канал на будущее (auto-reload не делаем).
Регистрация SW — **только в `import.meta.env.PROD`**: на dev SW не нужен
(не биться с HMR). Кнопка hard-reload на Главной — страховка для
задеплоенной сборки. Подробнее — `docs/00_NAVIGATOR-boom-cmd.md §6`.
